# Editor architecture and validation

## State and persistence

`EditorSession` owns the draft, stable profile/item IDs, selection, and up to 100 undo snapshots. Consecutive edits to one field merge for 650ms. Profile switching and hiding the window preserve drafts. Import is an undoable draft operation. The runtime reads only `ConfigManager`'s committed configuration.

Apply validates non-empty shortcuts/URLs, unique IDs, two-level hierarchy, triggers, and safe geometry. Empty targets and legacy None actions are valid placeholders. `PieItem::IsNoOp` lets the executor skip them before handler validation or dispatch, without a failure notification. `QSaveFile` writes atomically with direct-write fallback disabled. Only a successful commit replaces the runtime configuration and emits `ConfigChanged`. Parse/type errors, invalid imports, write errors, and failed file replacement retain the draft and original file. Configuration JSON remains version 1.0; legacy appearance aliases and existing custom colors are supported. Fresh configurations use Frost at approximately 96% effective sector opacity. Existing saved styles retain their values until edited or replaced by a preset.

Appearance writes always target the current profile's `StyleOverride`, including presets. `GlobalStyle` remains a read-only fallback for legacy profiles and seeds an independent style for newly created profiles. The first local edit copies the effective legacy style before changing a field; loading alone does not rewrite files or mark the draft dirty. Duplicating a profile copies its effective style. There is no shared/custom switch in the UI. Undo/redo, discard, apply, import, reload, profile switching, and runtime rendering preserve this isolation.

## UI and rendering

`SettingsWindow` owns the QML engine, session, recorder, and icon catalog. QML provides the toolbar, canvas, contextual inspector, organizer, and compact drawer. Shared buttons, menus, tooltips, fields, checkboxes, sliders, switches, and dialogs use `Theme.js` tokens. The three-dot menu toggles and suppresses its button tooltip while open. Apply/Discard keep their toolbar positions when disabled. Advanced controls do not replace the canvas. Submenu containers cannot be nested or converted to actions while they contain children.

`AppDialog` supplies the white rounded surface, modal focus, scrollable body, and fixed footer for settings, about, icon selection, color selection, running applications, and exit confirmation. `RunningApplications` only enumerates process names; QML handles search and selection. Quit confirmation is asynchronous, and a failed Apply leaves its dialog and draft open. File/folder selection remains a native dialog; the application requests the light color scheme. A duplicate launch activates the existing editor over a local socket; if activation is unavailable, a light QWidget notice explains that it is already running.

`ColorWheelItem` paints and hit-tests the hue ring and saturation/value square, retaining hue for achromatic colors. `ColorPicker` stages H/S/V/alpha and RGB/RGBA hex changes until confirmation; configuration colors retain Qt's ARGB representation. Selection IDs guard against applying a delayed result to a different item. The last 12 confirmed colors are stored separately in QSettings; isolated preview/test sessions do not write that history.

`WindowTitleBar` and `WindowResizeHandles` provide system move/resize with shared, unfilled caption buttons. Windows DWM supplies rounded corners where supported. Native maximize/restore preserves the Windows state, including taskbar-free monitors where Qt 6.9's frameless maximization can report FullScreen. The organizer tracks the dragged row by ID, draws an insertion gap, and commits one move on release; edge scrolling and Escape cancellation keep the draft stable during the gesture.

Reordering within a container preserves selection, including an empty selection. Moving an action to another container still follows the moved item. `ActionContextMenu` is shared by preview sectors, preview submenu rows, and organizer rows; it targets the clicked ID without selecting it first. Deleting a different action preserves the current selection. The preview hint does not depend on the Enabled switch.

The QWidget tray menu matches the QML menu's light surface, spacing, corner radii, and hover color. Application and tray ICO resources come from the supplied Pie-Menu-SVG-Pack, with the application SVG master retained under `resources/logo`. The GitHub button beside About uses the verified repository URL.

`PieScene` and `ListScene` share drawing, colors, geometry, and hit testing between `PiePreviewItem` and the runtime QWidget menus. Icons are supplied before painting. The preview composes its logical transform with the Qt Quick device-pixel transform and uses fixed label bounds centered on the menu origin, so renaming does not move or scale the menu. Runtime bounds still follow rendered text. Window placement accounts for negative monitor coordinates, label extents, screen edges, and small work areas. Long submenu lists page with the wheel or edge scrolling. Paint requests occur on changes, animation, or input; there is no idle repaint timer.

## Localization

`TranslationManager` installs an embedded Qt `.qm` catalog before constructing the editor and tray. English uses source strings; `zh-Hant` (including Taiwan, Hong Kong, and Macao) selects Traditional Chinese, and `zh-Hans` (including China and Singapore) selects Simplified Chinese. The first system UI language determines the automatic choice; unsupported languages fall back to English, as do missing translation entries. Explicit script subtags take precedence over region.

The existing JSON `language` field accepts `system` (new/missing-field default), `en`, `zh-TW`, or `zh-CN`. Existing explicit preferences are retained. Choosing a different language opens a restart prompt: Later retains the undoable draft, while Restart applies all pending changes before launching a replacement process. Save or launch failure keeps the current process open. On Windows the replacement waits for its parent to exit before taking the single-instance lock. Unknown imported language tags fall back to English. User-authored names, action payloads, shortcut tokens, and JSON enum values are never translated. New default names use the current interface language.

Chinese interfaces use Microsoft JhengHei UI for QML, native controls, and default menu text; custom menu fonts remain explicit overrides. English uses Segoe UI. Manual launches show the editor. The Windows Run entry includes `--autostart` to hide it, and is synchronized on normal startup to migrate older entries. A previously registered command without the flag can show the editor once during migration. A user-scoped local socket lets subsequent manual launches activate the existing editor; duplicate autostart launches exit quietly.

Translations live in `resources/i18n`. With the Qt Linguist Tools component installed, run `cmake --build build --target update-translations` after changing C++ or QML text, then fill both TS catalogs. Normal builds compile and embed them, so deployment needs no separate application translation files. Core tests cover locale resolution, fallback, embedded catalogs and preference persistence; UI tests open both Chinese editors and exercise the language selector at all four scale factors.

## Updates and release notes

`UpdateManager` performs one asynchronous request at normal startup to GitHub's [latest stable release endpoint](https://docs.github.com/en/rest/releases/releases#get-the-latest-release). Preview and smoke-test runs do not create an updater. Numeric version comparison rejects equal/older versions, draft/prereleases, and malformed tags. Offline, rate-limit and parsing failures leave normal operation unaffected; status is available in Settings. Requests have time and size limits and retain HTTPS through redirects.

`SettingsWindow` chooses a dialog for a visible editor and a native tray notification for a hidden/minimized editor. Clicking the notification or its persistent tray menu entry opens the notes. The dialog waits for existing modal work and recording to finish. Skipping persists the exact version in QSettings; newer releases remain eligible, and a manual Settings check can revisit a skipped version. The notes language is fixed to the interface language chosen at startup, not an unapplied language draft.

The update action fetches `SHA256SUMS.txt` and `GoPieMenu_Setup.exe` from the same validated repository/tag. Downloads stream to `QSaveFile` in the application cache, enforce the published file size, and must match SHA-256 before being marked ready. Nothing runs without the separate **Install and exit** confirmation. The editor resolves dirty drafts through its existing exit dialog, rechecks the saved installer, and uses Windows elevation to start it. Only successful launch emits the exit signal; save failures, corrupted downloads, and cancelled elevation leave the application open. Cached installers are retained so a running installer is not deleted during app shutdown.

`CHANGELOG.md` is the only release-note source. Each `## [x.y.z]` section contains `<!-- gpm:lang en -->`, `zh-TW`, and `zh-CN` blocks, each closed with `<!-- gpm:endlang -->`. Feature/fix/upgrade prose is localized; an optional `shared` block holds validation and comparison links once. Keep heading levels inside language blocks at `####` or deeper; reserve `## [version]` for releases. The application selects one language plus shared content, falls back to English when needed, and supports the unmarked English bodies of older releases.

To prepare a release, move completed entries from `Unreleased` into a numbered section and update both application/installer versions. Run `scripts/release-notes.ps1 -Version vX.Y.Z -OutputPath build/release-notes.md` to inspect the exact body. CI validates that version and all three nonempty language blocks before packaging; the publish job extracts the same section for `body_path`. It never publishes the whole changelog or the Unreleased section. This preserves the markers in the Release API body without another network request to the repository.

Update regression tests use fake network replies and fake installer launchers, covering version ordering, localization/fallback, persistent skip/manual revisit, timeout/HTTP errors, checksum/size rejection, retry/cancel, file tampering, and cancelled elevation. UI tests cover tray routing, modal deferral, all three languages at 800×520, and the dirty-draft installation flow at every DPI scale. `ReleaseNotesTests.ps1` checks extraction and rejects missing, duplicate, or malformed language/version blocks. Real Windows toast delivery and an actual UAC/installer run remain manual acceptance checks; tests never install software.

## Persistent menus and foreground arbitration

Each profile has a `displayMode` of `Shortcut` (the missing-field default) or `Persistent`. This is independent of its stored trigger, so changing display modes preserves the shortcut. JSON version remains 1.0. EditorSession treats the mode as an ordinary undoable draft field; runtime changes occur only after Apply succeeds. Persistent profiles do not require a recorded trigger.

`MenuPolicy` selects enabled, nonempty persistent profiles by application scope, then stable configuration order. A resident profile reserves its scope regardless of the global visibility toggle. `InputState` and `RuntimeMenuController` use the same policy: an app-specific resident blocks global triggers, and a global resident yields only to app-specific shortcuts. Equal-scope shortcuts do not displace a resident. Profiles scoped to an app but configured for shortcut activation do not reserve the slot until triggered.

`HookManager` listens for `EVENT_SYSTEM_FOREGROUND` through an out-of-context WinEvent hook on the UI thread and cancels transient input when foreground changes. It coalesces notifications onto a zero-delay timer and resolves the latest event's HWND: Windows can still report the old or null `GetForegroundWindow` during activation, even after the callback returns. If that HWND has already been destroyed, resolution falls back to the current foreground, retrying a null window after 50 ms without replacing the visible profile. Pending resolution stops when hooks are uninstalled. Action dispatch still checks the actual foreground process. `RuntimeMenuController` owns arbitration for a single `PieMenuWidget`: switching profiles resets the old main/submenu/context windows immediately, without overlapping close animations. Shortcut completion restores the eligible resident. Pause and recording suppress runtime display; configuration changes re-evaluate eligibility.

Persistent pie and list widgets accept press/release clicks without auto-closing. Center dragging uses a movement threshold and clamps placement to the screen work area; submenus follow the center. Submenu IDs, rather than indexes, identify remembered expansion. Each profile's center and expansion plus the global hidden toggle live under `persistent/` in QSettings, outside the editor draft. Preview/tests can use memory-only or temporary settings. Deleted submenu IDs are ignored on restore; off-screen positions are clamped when shown.

`NonActivatingWidget` applies Windows `WS_EX_NOACTIVATE` whenever Qt creates or recreates its native window, alongside Qt's no-focus/show-without-activating flags and nonactivating mouse/pointer activation responses ([Windows contract](https://learn.microsoft.com/en-us/windows/win32/winmsg/extended-window-styles)). Handling `WM_MOUSEACTIVATE` alone proved insufficient: a real cross-process click could clear the foreground window, leaving actions without a keyboard target. Pie and list event overrides must call this base class so native-window creation is handled. The center context menu uses the same nonactivating surface. Center Hide and the checkable tray action share one state. Outside pointer presses use Qt logical coordinates to match widget geometry at every DPI, and dismiss the center context menu without dismissing the persistent pie or submenu.

Regression coverage checks legacy/default mode loading, invalid mode rejection, undo/apply/reload, scope priority and hidden reservations, resident/shortcut handoff, repeated clicks, submenu toggle, center drag, context/tray synchronization, and position/expansion restoration. Native input tests use Windows `SendInput` against a separate target process at all four UI scale factors, verifying foreground retention, actual Ctrl+F24 delivery, pointer exit, drag, context actions, and real process switching/restoration. These tests require an interactive desktop and run serially. Third-party/elevated apps (including CSP), pen/touch hardware, and mixed-DPI monitor moves remain hands-on acceptance scenarios.

## Input and asynchronous work

`InputState` is a pure state machine behind the Win32 hook adapter. It handles sided modifiers, repeat suppression, matching swallowed releases, app-specific priority, hold/toggle confirmation, and Escape cancellation. The active trigger is a value snapshot. Self-generated input carries `OwnInputTag`, so sending an action does not retrigger the hook. Recording suspends hooks. Runtime widgets consume a selection before dispatch and reject input while closing.

The editor exposes Ctrl, Shift, Alt, and Win independently from activation mode, plus left/right/middle/X1/X2 mouse buttons. Keyboard recording preserves the chosen keyboard mode and does not convert a mouse-hold trigger to a keyboard trigger.

`IconCatalog` indexes filenames once and filters metadata without decoding thumbnails. The QML grid creates visible cells and two nearby rows. Search is coalesced for one frame (16ms). Managed worker pools load images; cancelled responses still finish, and stale generation results are ignored. The decoded-image cache is capped at 64 MiB and the GUI-ready cache at 16 MiB. Keys distinguish file modification time, raster dimensions (including DPI), and tint.

Resolution order is the writable application-data icon folder, the legacy executable-adjacent `icons` folder, then embedded resources. Absolute paths remain supported. Filesystem changes refresh the catalog and invalidate images. Engine shutdown waits for managed work. The response's final signal runs on its owning thread, following [Qt's response lifetime contract](https://doc.qt.io/qt-6/qquickimageresponse.html).

## Automated coverage

Run `scripts/build.ps1` as described in the README. CI uses the `windows-2022` runner to match the Visual Studio 2022 generator and passes the installed Qt SDK path explicitly. It sets a 1920×1080 desktop; interaction tests request a fixed 1160×760 logical viewport so scaling does not silently turn every case into a cramped-window test. Compact behavior is tested explicitly at 800×520. Native window placement and maximize tests still use the actual work area. CTest runs core once and the Windows QML UI at scale factors 1, 1.25, 1.5, and 2. Tests use temporary configurations, disable startup registry changes, and never execute actions.

- Core: draft isolation across profiles; undo/redo/apply/discard; safe selection after deletion; invalid imports and malformed persisted files; creation and atomic-replacement failures; legacy JSON; hierarchy-preserving moves; trigger state, including left/right Win modifiers with mouse and keyboard triggers; injected events; shortcut parsing.
- UI: canvas selection, typing, shortcut/trigger recording, profile creation/deletion and selector synchronization, menu toggle/tooltip behavior, stable preview geometry after renaming, icon centering/search/selection, whole-row drag insertion at both boundaries, autoscroll and cancellation, submenu editing, appearance, and Apply/hide/reopen.
- Dialog/window UI: color conversion, ring/square pointer input, hex validation and focus, confirm/cancel isolation and recent colors, modal shortcut blocking, unsaved exit success/failure/cancel, enabled switch, maximize/work-area/restore, running-app selection dialog, and compact color layout. Existing coverage includes the 800×520 drawer, QML warning detection, high-DPI painted coordinates, four-corner/negative-screen placement, a 100-item list, rapid menu reopen, and closing engines during icon loading.
- Packaging: `scripts/package.ps1` checks matching application/installer versions, deploys Qt/QML dependencies, runs `--smoke-test` with the SDK removed from PATH, and compiles the installer plus SHA-256 checksum. The smoke test uses preview isolation, verifies that a deployed TLS backend can load without making a network request, and exits after startup. CI uses the same script and retains test screenshots and logs. Version tags must match the application version and have a corresponding multilingual version section in `CHANGELOG.md`; publication waits for the build, tests, and packaging to succeed.

Additional checks cover independent profile appearance (including legacy defaults and custom styles), blank-action save/import, no-op dispatch through fake action handlers, selection-preserving sorting/deletion, all three action context-menu locations, disabled-menu hints, and tray Pause behavior. The GitHub test intercepts URL opening rather than launching a browser. Action dispatch is built as `gpm_actions` so the same production dispatcher can be tested without executing real actions.

## Local Release measurements

Measured on 2026-10-09, Windows 11, Qt 6.9.0 / MSVC 2022, software Qt Quick rendering, 1,377 embedded icons. Same development machine, four scale factors; warm opening sampled three times per scale.

| Operation | Observed range | Target |
| --- | ---: | ---: |
| Warm picker open and first rendered frame | 40–60ms | <150ms |
| Search text through filtered model, including 16ms coalescing | 21–25ms | <100ms |
| Cold metadata index | 51–65ms | Background, UI remains usable |
| Metadata filter alone | 0.089–0.153ms | <100ms |

Warm timing includes the test helper's 30ms layout wait. These are local samples, not latency guarantees or cross-device benchmarks. Logs are in `build/artifacts`; timing values are reported, not enforced as brittle CI thresholds.

The local Release build and all CTest entries passed. Deployed startup passed without an SDK PATH, and the Inno Setup installer compiled successfully. Published build results are available in [GitHub Actions](https://github.com/RyuuMeow/GoPieMenu/actions/workflows/windows-release.yml). Real keyboard/mouse feel in third-party apps, Windows-key combinations interacting with Start/system shortcuts, elevated target apps, and physically moving between monitors with different Windows scaling settings still require hands-on acceptance; uniform scale-factor tests do not simulate that hardware transition.
